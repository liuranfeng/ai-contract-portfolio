# 01 · 合同智能化工作台

**形态**：产品设计 + 本地可运行原型
**状态**：本地验证（本机通过 Dumate 模型跑通任务链路）；多方真人协作、客户私有化与生产验收未闭环

## 解决什么问题

单点审查工具只能回答「这份合同有什么风险」，但企业里真正跑的是流程：谁起草、谁能改、意见怎么收、什么时候清稿、签署前如何确认待签稿等于审定稿、履行阶段谁盯义务。工作台把这条链路做成有状态、有证据、有版本、有人工确认的系统。

## 产品结构

- **五大主线**：知识管理 / 起草与协作 / 审批与审查 / 签署与归档 / 履约与监督
- **三类角色 × 四阶段**：合同负责人、法务财务合规、领导审批人，分别对应生命周期四阶段（初生—成长—成熟—死亡）的操作与权限
- **职责边界**：任务、合同版本、意见处置由业务服务管理；Agent 只负责模型执行与产出，避免把流程规则写进提示词

## 关键设计取舍

| 取舍 | 结论 | 理由 |
| --- | --- | --- |
| 文档为中心 vs 表单为中心 | 文档为中心 | 合同最终交付仍是 Word，正文才是权威载体 |
| 清稿门槛 | 收齐全部协作意见才可清稿 | 避免意见遗漏导致返工 |
| 候选稿与正式版 | 严格分离 | AI 产出必须经人工确认才能进入正式版本 |
| 接入协议 | 与载体解耦的接入方式 | 不把产品绑死在某一个 Agent 宿主上 |

## 已实现并验证的部分

- 任务链路：起草 → 抽取 → 清单审查 → 协作建议 → 比对，共 5 类任务在本机模型上跑通
- 范本：预置并核验 27 类合同范本，保留原生定位、来源哈希与版本关系
- 受控交付：候选稿与正式版本分离、受控 Word 回传与报告导出；实测可拒收对正式版正文的篡改并保持版本不变
- 另完成覆盖多部门协作至签署归档的流程原型（设计态）

## 未闭环 / 不声称

- 客户私有化环境部署、与客户审批系统（流程引擎、合同系统）的联调
- 真实多方真人协作（演示中的部门流转为模拟）
- 生产验收与效果指标
