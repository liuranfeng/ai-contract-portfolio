# 02 · 招投标文件与合同交叉校验

**形态**：套件源码（5 个 Skill）+ 交互演示 + 离线验证
**状态**：离线验证（两组真实文件，长文档分别约 109 页与 330 页，已完成 PDF 导出）；未接客户生产环境

## 问题定义

招标提要求、投标作承诺，**但最终合同没有落实**。这类问题用条款替换式比对比不出来，因为它不是「两份文本哪里不一样」，而是「某个承诺在合同里到底有没有、有没有被弱化」。

## 为什么是「非置换式」校验

| 做法 | 局限 |
| --- | --- |
| 条款替换比对 | 只回答文本差异，不回答承诺是否落实 |
| 语义相似度匹配 | 相似 ≠ 落实；「按需协商」与「10 年备件供应」语义并不相似但义务完全不同 |
| **非置换式交叉校验** | 以义务为粒度：先把招标要求、投标承诺、合同条款各自结构化，再逐条判定「已落实 / 弱化 / 缺失 / 冲突」 |

## 原文证据层

- 以文档解析返回的 **layoutId** 作为唯一定位点，定位到具体段落
- **跨文档时 layoutId 会重排**，因此定位必须同时携带文档索引（如 T-01 / T-02 / C-01），否则结论会指回错误原文
- 每条结论绑定：来源文档 + layoutId + 原文片段，保证可回溯

## 交付物

- 报告形态：文档 + 关系连线 + 顶部事实冲突清单（先结论、后出处），不使用工作台式排布
- 长文档：按段拆分渲染，拆分后统一样式与页码；导出时保持可打印
- 导出：HTML 与 PDF 双形态，套件内含导出脚本与 PDF 校验脚本

## 套件结构（suites/tender-contract-verification）

| Skill | 职责 |
| --- | --- |
| tender-align | 招标要求与合同条款的对齐 |
| tender-facts | 事实抽取与结构化 |
| tender-evidence | 原文证据层与定位（含长文档分段、docx 修订参考） |
| tender-review / tender-audit | 逐项判定与交叉复核 |
| tender-verify / tender-report | 校验与报告渲染、导出 |

## 未闭环 / 不声称

- 客户生产环境接入、客户样本回归与现场性能
- 通用准确率、误报率等效果指标（离线验证只代表特定样本）
