# 04 · 数据与脱敏说明

## 数据来源

| 内容 | 来源 | 处理方式 |
| --- | --- | --- |
| 套件源码（suites/） | 本地工程目录 | 剔除缓存与运行产物；对个别文档中的项目名做了泛化 |
| 交互演示（demos/） | 为作品集重新制作的脱敏版本 | 全部使用合成公司名、合成条款、合成金额与日期 |
| 索引说明（docs/） | 作者本人整理 | 只描述产品结构、判定口径与状态，不含客户信息 |

## 本仓库不包含什么

- 客户名称、客户联系人、客户合同原文或任何客户数据
- 生产环境地址、账号、密钥与令牌（套件通过环境变量注入凭据，仓库内不含实际值）
- 客户的验收结论、报价与商务信息

## 状态口径

| 状态 | 本仓库中的对应内容 |
| --- | --- |
| 本地验证 | 工作台任务链路与受控回传、比对套件的本地工程样本验收、交叉校验的离线验证 |
| 方案 / 原型 | 全生命周期流程设计、部分产品结构的原型实现 |
| 客户验收 | **不包含**：本仓库不声称任何客户生产环境的验收结论 |

## 为什么强调这一点

企业 AI 产品最容易失真的地方，是把「设计目标」写成「已达成效果」。本仓库的所有描述都按上表口径标注：能跑通的写「本地验证」，只有设计的写「方案 / 原型」，没有证据的宁可不写。这也是我在客户现场做效果复核时使用同一条标准——区分「业务可接受性」「风险识别」与「替代条款可执行性」，不把编号引用率当作准确率。
