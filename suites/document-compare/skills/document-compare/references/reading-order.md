# 阅读顺序与长文档

## 两种编号

documentIndex + 原生 layoutId 用于定位；ordinal 用于阅读，不替换原生 ID。不同文档同名 layoutId 合法。数值 1 与字符串 "1" 不混淆；同一文档重复 ID 拒绝导入。跨分片 ID 重复时必须保留分片文档索引和原始文档/页码映射，不能将同名 ID 合并；当前双文档导入器要求每份输入的 ID 唯一，缺映射时保留问题并停止该份导入。

pages 数组是页阅读序列。页内显式 reading_order（或 readingOrder）存在时要求每块都有且唯一；否则使用布局数组顺序。多栏 PDF 若服务没有保证正确顺序，应人工确认/使用真实 reading_order 后再比较，不用 bbox 的简单 y 排序冒充阅读顺序。

## 对齐与比较

以规范化文字的唯一锚点确定单调骨架，锚点间动态规划允许 1:1、1:2、2:1、1:3、3:1 关联。规范化仅用于对齐，不改变原文或字符判断。归并布局比较时插入显式换行；拆段本身可形成字符差异，语义仍可能一致。

相似度过低的配对标为 unresolved。没有锚点的大窗口超过 max-cells（默认 16000）时完整保留为未决窗口，不能只取前 N 页或强制按位置相配。用完整阅读和 --alignment 明确对应关系后重跑；变动导致新 comparisonId，旧语义判定不沿用。

超长单 layout 保留整块。字符算法先按文本/行分层产生覆盖完整左右文本的区间，超过 20000 字符的大片变化允许较粗 replace 并给提示，不承诺编辑区间最小。UI 保留原布局排版及精确差异文本；展开/定位不依赖把长表截断。

## 模型阅读

semantic-requests 文件保存所有原文请求和前后项。超出模型单次输入时，逐项读取或运行：

```text
python scripts/compare.py read-window --input comparison.json --id D0001 --side left --start 0 --length 6000
```

依照 nextStart 读到 null，再读另一侧；记录实际已读区间。序号和 layout 引用保持不变，窗口只是阅读视图，不生成新的原生 ID。对跨页表格同时检查表头、续表条件和上下文，未读完不能给完整结论。最终一个对齐事项只回填一次综合语义结论，不用局部窗口结果覆盖全段。

扫描/OCR 漏字不能由比对算法补正。疑似误识别标 uncertain，并回到原件核实；修改后的解析需保存新快照，原始服务返回不可覆盖。
