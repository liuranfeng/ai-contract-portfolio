# 文档式报告、渲染图与 PDF

保持已经批准的文档式结构：上部主要发现和范围，下部逐主题比较、两侧原文 Diff、关系连线、解释性上下文；历史事项与完整原文索引位于附录。不采用侧栏工作台。

## 单一报告生成链

实质判断写入 snapshot 的 expectationComparison 和 reportView（见 tender-evidence/references/data-contract.md）。随后调用 evidence.py report；不得在测试目录用字符串替换、临时函数替换或硬编码结论生成另一份“正式”报告。旧快照不具备新字段时保持旧展示，不自动猜测预期结果。HTML/Markdown/JSON/manifest 一起交付。

每一个复合引用最终定位到同一快照的 documentIndex + 原类型 layoutId；不同分片相同 ID 不混淆。页码优先展示经过映射的 originalPage。原文逐字保留并转义；表格原生 Markdown 和原版面是证据，结构化比较表是分析。没有可靠表格结构时不为了美观改写证据；不得执行文件内 HTML、脚本或加载签名图片链接。

### 阅读层与原始层（1.2.1）

document_display.py 对展示副本执行结构渲染：Markdown 表格/标题/列表、加粗、下划线和允许的静态 HTML 表格；保留已有 rowspan/colspan，不推断合并单元格。HTML 属性只保留受限跨度和对齐；脚本、事件、嵌入对象及外部资源不执行。图像无已归档资源时显示“原文图像：见原件”，不显示原始标签和签名地址，不声称恢复了图像内容。未知复杂公式可能保持字面文本，不凭猜测改数值。

正文 Diff 在渲染后的可见文字上计算，再将 mark 加入文字节点，避免破坏表格或把标签差异当内容差异。此阅读层是结构化还原，不是原 PDF 像素复刻；原件仍是版面最终依据。JSON/layout.text/quotes 和 Markdown 审计报告原样保留。完整来源索引提供阅读层及“查看原始解析文本”折叠区，打印使用阅读层，原始解析源码不自动打印。

首页优先展示主要主题的状态数量与差距影响，材料范围收进可展开说明但缺件、待复核数仍在首页显式提示。事项正文先显示已有 impact，再显示预期/合同对照，完整 reason 可展开；不自动删减结论或生成更严重的判断。

## 浏览器导出

需要本地 Node.js 22+ 与 Chromium、Chrome 或 Edge。脚本自动发现常见安装路径，其他位置用 --chrome 指定，不能默认宿主具有浏览器或网络权限。

```text
node <套件>/skills/tender-report/scripts/export_report.cjs --html <报告>/report.html --out <新导出目录> --pdf --screenshots
node <套件>/skills/tender-report/scripts/export_report.cjs --html <报告>/report.html --out <新完整打印目录> --pdf --mode full --timeout 1200000
```

默认输出 report.pdf、report-desktop.png、report-evidence.png、report-mobile.png、export-manifest.json。manifest 记录源 HTML 摘要、各产物摘要、运行成功/失败、浏览器版本和交互检查。截图是代表页面，不等同于逐页核验。保留源 HTML，不把截图转换成整篇 PDF。浏览器只访问本地文件，阻止 HTTP(S) 资源加载；独立临时浏览器配置隔离用户会话，结束时仅关闭本次进程。

脚本验证锚点、重复 DOM ID、桌面横向溢出、Diff 开关和一次证据跳转；截图导出时另查窄屏横向溢出。PDF 采用 A4 横向、背景色和页码，保留文本及连线；关闭昂贵的结构标签生成，不以此宣称 PDF/UA 无障碍合规。

## 打印范围与超长输出

- report（默认）：正文和正文必要上下文展开，历史记录与完整原文附录保持折叠。目录仍保留；PDF 不具备 HTML 的点击展开能力。交付说明此范围，保留可交互 HTML。
- 同一事项内，若某上下文与证据卡来源锚点相同，且完整上下文文字已包含在该卡原文中，正文打印可以折叠重复上下文并注明原文已在证据卡展示。不同来源、仅部分摘录或其他事项中的相似文本不满足条件，仍须展开。共享 tenderPreparePrint 同时服务页面打印与导出脚本，manifest 记录去重数量；不修改原始证据或删除独有上下文。
- full（显式）：全部附录和原文展开。先估算记录数量；大量重复证据可能产生数百或更多页。用户要求全部材料时不能静默切换成正文模式。
- 页面内“完整附录”选项与上述范围一致。打印后恢复原展开状态；不再无条件展开数千条隐藏记录。
- 只在浏览器内移除折叠元素的不可见子节点以减少打印开销，原 HTML 和 JSON 字节保持不变。打印前解除证据区域滚动高度，长卡片允许跨页，关系配对保持同一比较区域；不截断长证据、不缩到不可读字号。
- 超时先看 manifest：识别启动失败、加载失败还是打印失败；权限问题使用宿主授权流程。保持已成功产物，只对失败输入另选新目录重跑，可提高 --timeout，不能把不完整输出当成功。不要无界重试或访问用户浏览器会话。
- full 仍过大时，按完整事项或附录章节分卷，并在封面声明每卷事项范围、原报告摘要及卷号。全卷合起来应覆盖全部计划事项；跨卷引用标注目标卷/原 HTML 位置，不能产生空锚点。不要直接截断 HTML 字符串或把一个事项的主要关系拆到不相干卷。当前自动脚本不提供分卷，须宿主明确构建分卷清单后分别生成，不能宣称已经自动完成。

## PDF 验收

用 PDF 解析器重开全部页，核对页数、文字可提取性及明显空页；再渲染首页、首个证据页、最长表格/卡片跨页处和末页抽查。检查中文字体、差异颜色、左右关系线、页码、正文截断和溢出。可用脚本：

```text
python <套件>/skills/tender-report/scripts/verify_pdf.py <导出>/report.pdf <新检查目录>
```

该脚本需要 pypdf 与 pypdfium2，只做机械检查并输出抽查图；人工/代理看图后才能报告视觉检查完成。工具缺失时使用宿主 PDF 工具或记录未完成，不伪称检查通过。
